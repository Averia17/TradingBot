# ADR-005 — Раздельные PostgreSQL и HTTP между владельцами данных

**Статус:** принято. **Дата:** 24.11.2026.

## Контекст

В исходном локальном стеке API, процессы paper и relay использовали один
PostgreSQL. Отказ или восстановление этого экземпляра затрагивали весь
торговый контур. Relay имел доступ к таблицам счёта и очереди доставки.

## Решение

| Владелец | Данные и транзакции |
|---|---|
| Trading API | Исследовательские задания, снимки, аренды и бюджет. Постановка задания и запись контекста его применения фиксируются вместе. |
| Accounts | Счета, резервы, позиции, исполнения и их outbox. Изменение счёта и событие фиксируются вместе. |
| Trade Events | Очередь pgqueue и тестовый вход событий. Relay читает outbox Accounts по HTTP и подтверждает событие после фиксации в своей очереди. |
| Portfolio Analytics | Проекция счёта и оценки из Kafka в отдельном PostgreSQL. |

Trading API сохраняет публичные paper-маршруты через клиент Accounts.
Планировщики, `orders` и публикация котировок работают через HTTP.
Новый заказ сверяет версию счёта и хеши у владельцев данных. При сетевом
сбое повтор восстанавливает ту же заявку и точные суммы. Research worker
пользуется публичным протоколом заданий. Внутренние ручки требуют bearer.

Идентификатор события и его точный payload позволяют Trade Events
повторить handoff после ошибки ACK. При недоступности Accounts
опубликование уже принятых заданий из pgqueue продолжается. Доставка
в Kafka допускает повторы. Потребители применяют свои правила дедупликации.

## Последствия

Локальный Compose запускает отдельные экземпляры и тома для владельцев
данных. Закрытые сети хранения подключают только владельца базы. Локальный
генератор передаёт отдельные credentials для paper-операций и чтения
outbox через тома выбранным процессам. Эта
проверка относится к отказу одного PostgreSQL. Независимое размещение,
резервирование хоста и эксплуатационные credentials для production
остаются отдельными задачами.

Данные общего прототипа заменяются чистой инициализацией. В диагностику
попадают наблюдения из отдельных snapshot каждого владельца. Для
восстановления согласованного состояния на время backup останавливают
запись и восстанавливают оба авторитетных хранилища по одному checkpoint.
